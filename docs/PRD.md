## 一、项目背景（Background）

随着 AI Agent 技术的发展，越来越多的开发者开始使用 ChatGPT、Claude、DeepSeek 等 AI 工具辅助开发。然而，目前大多数 AI 产品都存在以下问题：

- 只能进行一次性的聊天，无法持续理解整个项目
- 无法长期沉淀开发过程中遇到的问题及解决方案
- 面试过程中产生的大量问题、反馈和建议难以统一管理
- 项目文档、PRD、README、简历等内容分散，缺乏持续更新机制
- AI 无法根据项目的发展持续学习和优化

对于一个持续数周甚至数月的项目而言，开发者真正需要的不是一次性的 AI 问答，而是一个能够长期陪伴项目成长的 AI 助手。因此，设计并开发 CareerPilot AI。

---

## 二、产品定位（Product Position）

CareerPilot AI 是一款基于 Multi-Agent 的长期项目成长助手（AI Project Growth Assistant）。

产品以 **Project（项目）** 为核心对象，通过多个智能体协同工作，持续收集、整理、分析和优化整个项目生命周期中的知识、问题、经验以及面试反馈，帮助开发者形成完整的成长闭环。

**核心价值主张**：
- AI 不只是聊天工具，而是长期参与整个项目生命周期
- 从"记录工具"升级为"主动驱动成长的助手"
- 让 AI 主动发现问题、提供优化建议，而不是被动等待用户整理

## 五、核心痛点

### 5.1 项目知识越来越多

```
开发过程中产生：
├── 技术问题
├── Bug
├── 架构设计
├── Prompt 优化
└── 部署过程

最终结果：
├── 全部散落
├── 无法快速查找
└── 重复踩坑
```

### 5.2 面试经验无法沉淀

```
每次面试产生：
├── 面试问题
├── 回答内容
├── 面试官反馈
└── 后续学习建议

最终结果：
├── 保存在聊天记录或 Word 文档
├── 随着面试次数增加，难以管理
└── 无法形成持续成长
```

### 5.3 项目文档不断修改

```
需要维护的文档：
├── README
├── PRD
├── STAR
├── 项目介绍
└── 简历

最终结果：
├── 没有统一管理
├── 不知道为什么修改
└── 容易遗漏更新
```

### 5.4 AI 无法持续成长

```
传统 AI 的问题：
├── 每次都是新的开始
├── 不知道昨天讨论了什么
├── 不知道项目做到哪里
├── 不知道哪些问题没解决
└── 无法真正参与长期项目
```

## 八、核心功能模块

### 8.1 Project（项目管理）

**描述**：一个项目对应一次长期开发。

**功能**：
- 创建、编辑、删除项目
- 项目列表和详情查看
- 项目状态管理（活跃、归档、删除）
- 项目统计数据（聊天数、知识数、经验数、面试数）

**示例项目**：
- CareerPilot AI
- 视觉检测系统
- RAG 平台
- Agent Demo

### 8.2 Chat（聊天系统）

**描述**：提供 ChatGPT 风格聊天界面，所有聊天均属于某一个 Project。

**功能**：
- 创建、编辑、删除聊天
- 流式消息响应（SSE）
- 多 Agent 协同响应
- 聊天历史记录
- 上下文理解

**交互流程**：
```
用户输入 → Coordinator Agent → 意图识别 → 调用对应 Agent → 整合结果 → 返回用户
```

### 8.3 Knowledge（知识管理）

**描述**：支持上传文档，AI 自动完成解析、分块、嵌入、检索。

**功能**：
- 上传文档（PDF、Word、Markdown、TXT）
- 自动文档解析（Unstructured）
- 文本分块（Chunking）
- 向量嵌入（Embedding）
- RAG 检索
- 项目知识库和全局知识库

**技术实现**：
```
文档上传 → 文件解析 → 文本分块 → 向量嵌入 → ChromaDB 存储
用户查询 → 向量检索 → Top-K 结果 → Prompt 组装 → LLM 生成
```

### 8.4 Experience（开发经验）

**描述**：用于管理开发过程中遇到的问题和解决方案。

**功能**：
- 记录 Bug、技术方案、架构决策、踩坑记录、学习总结
- AI 自动整理
- 形成项目成长记录
- 标签分类
- 置顶功能

**示例**：
```
标题：Docker 部署权限问题
类型：bug
内容：Docker 容器内无法写入文件，报错 Permission denied
解决方案：将用户加入 docker group: sudo usermod -aG docker $USER
标签：[docker, permissions]
```

### 8.5 Interview（面试成长）⭐ 核心特色

**描述**：整个产品最大的特色，支持面试全流程管理。

**功能**：
- 记录面试信息（公司、职位、日期、状态）
- 记录面试问题和回答
- 记录面试官反馈和建议
- AI 自动分类、总结、统计
- 识别薄弱点，生成学习建议
- 形成 Interview Timeline
- 面试统计（按公司、按类别、时间线）

**统计示例**：
```json
{
  "weak_areas": [
    {
      "category": "Redis",
      "avg_rating": 2.5,
      "suggestion": "建议深入学习 Redis 持久化机制和集群部署"
    }
  ],
  "by_company": [
    {
      "company": "字节跳动",
      "count": 3,
      "offer_rate": 0.67
    }
  ]
}
```

### 8.6 Documents（AI 文档管理）

**描述**：AI 自动维护项目文档。

**功能**：
- 自动维护：README、PRD、STAR、项目介绍、简历
- 每次项目更新，AI 自动建议同步更新
- 支持版本管理
- 记录修改原因

**文档类型**：
| 类型 | 说明 |
|------|------|
| readme | 项目 README |
| prd | 产品需求文档 |
| star | STAR 法则项目描述 |
| resume | 简历项目经历 |
| project_intro | 项目介绍 |

## 十四、PRD 升级建议

### 让 AI 主动驱动成长

当前产品围绕 Project 管理问题和面试已经很不错，但还可以再提升一个层次：**让 AI 主动驱动成长，而不是用户主动整理**。

#### 建议 1：薄弱点自动学习计划

当检测到多次面试都暴露同一个薄弱点（如 Redis、高并发），AI 自动生成学习计划并关联到对应项目。

#### 建议 2：架构变更自动提醒

当项目架构发生变化时，AI 自动提醒 README、PRD、简历项目描述可能需要更新。

#### 建议 3：知识库变更影响分析

当新的知识库文档上传后，AI 自动分析是否会影响已有方案或面试回答，并给出建议。

**这样，产品就不仅是一个"记录工具"，而是一个真正的长期项目成长助手。**
