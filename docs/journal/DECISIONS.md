## Decision #1: LLM 引擎选型

**日期**: 2024-01-25
**阶段**: Phase 0 - 技术选型
**状态**: ✅ 已决定

### 背景
需要确定V1阶段使用哪个LLM引擎

### 选项分析

#### 选项A: 仅使用OpenAI
- 优点: 效果好，API稳定
- 缺点: 需要付费，有网络限制
- 工作量: 低

#### 选项B: 仅使用Ollama
- 优点: 免费，本地运行，隐私好
- 缺点: 效果一般，需要部署
- 工作量: 中

#### 选项C: 双引擎支持（✅ 选择）
- 优点: 灵活，开发用Ollama，生产用OpenAI
- 缺点: 开发量稍大
- 工作量: 中

### 最终决定
**选择选项C**，同时支持OpenAI和Ollama，通过配置切换

### 原因
1. 开发阶段使用Ollama，节省API费用
2. 生产环境使用OpenAI，保证效果
3. 配置切换机制不复杂

## Decision #2: 数据库选型

**日期**: 2024-01-25
**阶段**: Phase 0 - 技术选型
**状态**: ✅ 已决定

### 背景
需要确定V1阶段使用哪个数据库

### 选项分析

#### 选项A: SQLite（✅ 选择）
- 优点: 无需安装，配置简单，适合开发
- 缺点: 不支持并发，不适合生产
- 工作量: 低

#### 选项B: PostgreSQL
- 优点: 功能强大，适合生产
- 缺点: 需要安装配置
- 工作量: 中

### 最终决定
**V1使用SQLite，V2迁移到PostgreSQL**

### 原因
1. SQLite零配置，便于快速开发
2. SQLAlchemy ORM支持数据库切换
3. V2迁移时只需改配置

## Decision #3: Git 工作流

**日期**: 2024-01-25
**阶段**: Phase 0 - 开发规范
**状态**: ✅ 已决定

### 背景
需要确定团队的Git工作流

### 最终决定
**使用 GitHub Flow**

### 流程
```
main (生产)
  └── develop (开发)
        └── feature/* (功能分支)
              └── PR → Merge → Deploy
```

### 原因
1. 流程简单，适合小团队
2. GitHub原生支持
3. 便于CI/CD集成

## Decision #4: 前端框架选型

**日期**: 2024-01-25
**阶段**: Phase 0 - 技术选型
**状态**: ✅ 已决定

### 最终决定
**Vue3 + Vite + Element Plus + Pinia**

### 原因
1. Vue3 生态成熟，中文文档好
2. Vite 开发体验好，速度快
3. Element Plus 组件丰富
4. Pinia 是Vue3官方推荐的状态管理

## Decision #5: 后端框架选型

**阶段**: Phase 0 - 技术选型
**状态**: ✅ 已决定
